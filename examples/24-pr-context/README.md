# Example 24: PR Context Generation

When an AI agent works on a feature or bug fix, ctxl tracks every prompt,
decision, file change, and `.ctx` update made during the session. The
`ctxkit pr` command collects this session data and renders it as a
structured PR description. This gives reviewers full visibility into what
the agent did, why it did it, and what context it used -- without requiring
the reviewer to read through chat logs.

## What This Demonstrates

- Generating a PR description from session data
- The PR context format (markdown and JSON)
- What data is collected: prompts, decisions, file changes, .ctx updates
- Posting the PR context directly to GitHub with `--gh`
- Customizing the output format

## How PR Context Generation Works

### Data Collection

During a coding session, ctxl's hooks and daemon collect:

| Data Point         | Source                    | Description                          |
|--------------------|---------------------------|--------------------------------------|
| Prompts            | UserPromptSubmit hook     | Every user prompt sent to the agent  |
| Decisions          | PostToolUse hook          | Architectural choices made during the session |
| File changes       | PostToolUse hook          | Files created, modified, or deleted  |
| .ctx updates       | PostToolUse hook          | Changes to .ctx files (proposals applied) |
| Tool calls         | PreToolUse/PostToolUse    | Which tools were invoked and their results |
| Errors             | PostToolUseFailure        | Failed tool calls and recovery actions |
| Session metadata   | SessionStart/SessionEnd   | Start time, end time, agent name     |

### Rendering

When you run `ctxkit pr --branch`, ctxl:

1. Identifies the current branch and its base branch (main/master)
2. Finds all sessions that were active while commits on this branch were made
3. Collects the session data (prompts, decisions, changes)
4. Renders the data as a structured markdown document

### PR Context Sections

The generated PR description includes:

| Section              | Content                                               |
|----------------------|-------------------------------------------------------|
| Summary              | Auto-generated summary of all changes                 |
| Session Timeline     | Chronological list of sessions with start/end times   |
| Key Decisions        | Architectural decisions made during the session       |
| File Changes         | Files created, modified, deleted with brief descriptions |
| .ctx Updates         | Changes to context files (added entries, updated entries) |
| Prompts              | The user prompts that drove the work (optional, can be excluded) |
| Context Used         | Which .ctx entries were injected during the session   |

## Try It Out

### Step 1: Generate PR context for the current branch

```bash
ctxkit pr --branch
```

Expected output (renders to stdout as markdown):

```markdown
## PR Context: feat/add-oauth-support

**Branch:** feat/add-oauth-support (3 commits ahead of main)
**Sessions:** 2 sessions (total duration: 1h 45m)
**Agent:** claude-code

### Summary

Added OAuth2 support to the authentication module. Integrated Google and
GitHub as OAuth providers. Updated the auth handler to support the OAuth
callback flow, added a new oauth.ts service, and updated the auth .ctx
file with the new key_file entry and a gotcha about RS256/HS256.

### Key Decisions

1. **OAuth2 with PKCE flow** (session sess_abc123)
   Used PKCE instead of implicit flow for better security with public
   clients. This aligns with current OAuth 2.1 recommendations.

2. **Separate oauth.ts service** (session sess_abc123)
   Created a dedicated service file rather than adding OAuth logic to
   the existing handler. Keeps the handler focused on HTTP concerns.

### File Changes

| File                      | Change   | Description                          |
|---------------------------|----------|--------------------------------------|
| src/auth/oauth.ts         | Created  | OAuth2 provider integration          |
| src/auth/handler.ts       | Modified | Added OAuth callback endpoint        |
| src/auth/types.ts         | Modified | Added OAuthProvider, OAuthToken types|
| tests/auth/oauth.test.ts  | Created  | OAuth flow integration tests         |

### .ctx Updates

| File           | Change                                           |
|----------------|--------------------------------------------------|
| src/auth/.ctx  | Added key_files entry for oauth.ts               |
| src/auth/.ctx  | Added gotcha: RS256/HS256 algorithm mismatch     |
| src/auth/.ctx  | Updated summary to mention OAuth                 |

### Session Timeline

| Session      | Start               | End                 | Duration | Prompts |
|--------------|---------------------|---------------------|----------|---------|
| sess_abc123  | 2026-03-14 09:00    | 2026-03-14 10:15    | 1h 15m   | 8       |
| sess_def456  | 2026-03-14 14:00    | 2026-03-14 14:30    | 30m      | 3       |

### Context Used

The agent used the following .ctx entries during this work:

- src/auth/.ctx -> summary (locality: 1.0, score: 0.92)
- src/auth/.ctx -> key_files/handler.ts (locality: 1.0, score: 0.90)
- src/auth/.ctx -> contracts/auth-security-requirements (score: 0.95)
- .ctx -> contracts/const-002-jwt-auth (score: 0.95)
```

### Step 2: Generate PR context as JSON

```bash
ctxkit pr --branch --format json
```

This produces a machine-readable JSON document with the same data. Useful
for CI pipelines or custom rendering.

### Step 3: Post PR context directly to GitHub

```bash
ctxkit pr --branch --gh
```

Expected output:

```
PR context posted to: https://github.com/org/repo/pull/42

Updated PR #42 description with ctxl session context.
```

This uses the GitHub CLI (`gh`) under the hood to update the PR description.
If no PR exists for the current branch, it creates one.

### Step 4: Exclude prompts from the output

If you do not want user prompts included in the PR description (e.g., for
privacy), use the `--no-prompts` flag:

```bash
ctxkit pr --branch --no-prompts
```

### Step 5: Generate context for a specific branch

```bash
ctxkit pr --branch feat/add-oauth-support
```

## Key Takeaways

- `ctxkit pr` generates structured PR descriptions from session data,
  giving reviewers full visibility into the AI agent's work.
- The PR context includes a summary, key decisions, file changes, .ctx
  updates, and the session timeline.
- Use `--format json` for machine-readable output and `--gh` to post
  directly to a GitHub pull request.
- All data is collected automatically by ctxl's hooks during the coding
  session -- no manual annotation required.
- Use `--no-prompts` to exclude user prompts from the output if privacy
  is a concern.
